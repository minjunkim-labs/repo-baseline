# 코어는 모델 이름이 아니라 모델 층을 정한다

코어는 일마다 모델 층(가벼움·보통·무거움)과 effort(낮음·보통·높음)만 정한다. 실제 모델 이름은 사용자 쪽의 층 표 한 곳에만 둔다. 이 저장소를 여러 에이전트 도구로 개발하고, 모델은 계속 새로 나오기 때문이다. 코어에 이름을 넣으면 도구를 바꾸거나 모델이 오를 때마다 코어와 모든 소비 레포가 바뀐다.

## 고른 것과 버린 것

- 기준: 일의 종류(구현·리뷰·읽기 전용 조사·기계적 작업)로 고르고, 리뷰에만 등급을 더한다. 등급은 `review-preflight`가 diff로 정하므로 구현을 시작할 때는 아직 없다. 등급을 미리 짐작하는 방법은 버렸다. 짐작이 틀리면 PR 중간에 층을 바꿔야 한다.
- 층 표를 둘 곳: 사용자 쪽 파일 하나를 골랐다. 사용자 전역 지시가 그 경로를 가리킨다. 도구와 구독은 사람의 사정이고, 모델이 오를 때 고칠 곳이 하나다. 저장소마다 두는 방법은 버렸다. 같은 표를 복사하고 모델이 오를 때마다 PR이 생긴다. 도구의 에이전트 정의 파일에 두는 방법도 버렸다. 저장소에 두면 민감한 파일이라 고칠 때마다 어려움 PR이 되고, 한 도구가 다른 도구의 폴더를 읽어 모델 ID가 섞일 수 있다.

## 대가

- 층 표가 없는 사람이나 도구는 부른 세션의 모델을 물려받는다. 개발은 되지만 비용은 줄지 않는다.
- 계열을 따라가는 별칭이 없는 도구는 모델이 오를 때 층 표의 칸을 손으로 고친다.
- 도구가 모델을 조용히 바꿀 수 있어서 바닥(어려움 리뷰는 무거움·높음)은 설정만으로 지킬 수 없다. 리뷰어가 실제로 돈 모델을 PR의 Review 칸에 적는다.
