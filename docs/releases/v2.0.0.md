# v2.0.0

repo-baseline의 첫 태그다. 소비 레포는 [docs/start.md](../start.md)대로 새 저장소면 `init`, 이미 있는 저장소면 `migrate`로 적용한다.

아래는 2026-11-22부터 이 태그까지 `changelog.d/`에 쌓인 v2 항목을 파일 이름 순서로 모은 것이다. 2026-11-17~2026-11-21 항목은 v1 도구(`templates/`, `profiles/`, `tools/`)를 쓰는 소비 레포가 옮길 일이다. `migrate`로 옮기면 따로 옮기지 않는다. 그 항목은 [d2360f6의 changelog.d/](https://github.com/minjunkim-labs/repo-baseline/tree/d2360f6e8b5ec81638d3132a9b92ac73ec2f6649/changelog.d)에 있다. 그 전 기록은 [CHANGELOG.md](../../CHANGELOG.md)다.

- v2 `baseline.py`(`init`·`check`·`run`·`budget`)와 `core/` 최소 코어를 더했다. 아직 소비 레포가 옮길 일은 없다(#175의 「옮기는 순서」를 따른다).
- v2 코어에 `REVIEW.md`(관리 블록)와 `.github/pull_request_template.md`를 더하고 `AGENTS.md`를 다시 썼다. `POLICY.md`는 v2 판 한 쪽이 됐다. `.baseline/`이 없는 v1 소비 레포는 `POLICY.md` 첫머리의 v1 판 링크를 따르면 되고, 손으로 옮길 일은 없다.
- `baseline.py enqueue <PR> <SHA>`: 문서·쉬움 PR을 다시 확인하고 `expectedHeadOid`로 머지 큐에 넣는다(로컬 전용). 코어에 `.claude/settings.json`(deny, 빈 allow·ask, `baseline.py`의 sha256을 고정한 `PreToolUse` 훅)과 관리 파일 `.claude/hooks/allow_enqueue.py`가 생겼다. v2로 옮기는 소비 레포는 이미 있는 `.claude/settings.json`에 이 칸을 합친다.
- `prompts/retro.md`에 막는 순서(구조 > 타입 > 린트·검사 > 테스트 > `REVIEW.md` > `AGENTS.md`), 래칫, 반대 패턴과 멈춘 곳, `/doctor prompt-audit` 절을 더했다. 소비 레포가 옮길 일은 없다.
- `baseline.py review-preflight <PR>`: GitHub REST만 써서 등급(문서·쉬움·어려움)과 이유, `.env*` 이름, fork 여부, diff 명령을 출력한다. upgrade 예외(태그 `v<판>`의 바이트와 같음)와 Dependabot 예외(PR 작성자 login과 브랜치의 모든 push가 `dependabot[bot]`, 버전·해시 줄만, minor·patch만)를 판정한다. `prompts/review.md`를 v2용으로 줄였다(v1 저장소는 고정 링크의 v1 판). `budget`이 리뷰어 읽기 13,000바이트를 잰다. `check`가 부모 폴더의 symlink도 거부한다. 소비 레포가 옮길 일은 없다.
- repo-baseline 자신이 v2 코어(`.baseline/`, 관리 블록)를 쓴다. v1 소비 레포의 PR 템플릿 원본은 `templates/core/pull_request_template.md`로 옮겼다. 소비 레포가 v2로 옮길 때까지 `sync_consumers.py`를 돌리지 않는다.
- v2 코어에 Stop 훅 `.claude/hooks/check.py`(관리 파일)와 그것을 셸 없이 부르는 `.claude/settings.json`의 `hooks.Stop`을 더했다. 작업 트리가 바뀐 턴에만 `run check`를 돌리고, 실패하면 Claude에게 되돌려 보낸다.
  `.claude/settings.json`은 관리 파일이 아니다. 이미 이 파일이 있는 소비 레포는 `core/.claude/settings.json`의 `hooks.Stop` 항목을 손으로 합친다.
- v2: `skills-bump`는 바꿀 스킬 폴더에 커밋하지 않은 변경이 있거나 쓰는 경로에 symlink가 있으면 아무것도 쓰지 않고 멈춘다. 소비 레포가 할 일은 없다.
- `baseline.py doctor`가 판, WSL, 같은 이름 개인 스킬, autoMode.environment, 신뢰되지 않은 .mise.toml, 샌드박스용 bubblewrap·socat을 보고 고치는 명령을 출력한다. 사용자 설정은 자동으로 쓰지 않는다.
- v2: 판을 고정한 스킬 사본(`.claude/skills/`, 원본은 `skills/`와 `skills.lock.json`)과 Matt 스킬 설정 `docs/agents/`를 관리 파일로 더했다. 소비 레포는 `upgrade` 때 함께 받고, 같은 이름의 프로젝트 스킬이 있으면 다른 이름으로 옮긴다. 새 판은 `skills-bump`와 주간 Issue로 올린다(`WORKFLOW.md`).
- `baseline.py upgrade <태그>`: 관리 블록·관리 파일·스킬 사본을 그 태그 판으로 바꾸고 `baseline.json`을 갱신한다. 소비 레포에서 고친 관리 블록이 있으면 멈추고 diff를 보인다. 결과 PR은 upgrade 예외로 쉬움이다.
- `enqueue`가 봇이 자기 댓글을 고친 시각을 외부 리뷰로 세지 않는다. CodeRabbit이 본문 수정마다 요약 댓글을 고쳐 쉬움 PR이 큐에 들어가지 못했다. 소비 레포는 upgrade로 `.baseline/baseline.py`와 `.claude/settings.json`의 고정 해시를 함께 받는다.
- `github plan|apply`가 `codeql_workflow.path`에 적은 workflow 파일을 읽고, Actions 정책이 `selected`가 아니면 허용 action 목록을 건너뛴다. 에이전트 deny 줄은 `Bash(*baseline.py*github*apply*)`로 넓어졌으므로 v2 저장소의 `.claude/settings.json`에서 같은 줄을 바꾼다.
- 어려움 PR은 리뷰 뒤 바뀐 부분이 문서뿐이거나 리뷰 지적을 그대로 고친 것이면 다시 리뷰하지 않고, 소유자가 병합 전에 diff로 본다(POLICY §5). 그 커밋과 까닭을 PR 본문 Review 칸에 적는다.
- 도구의 지침(프로젝트 지침, 전역 규칙)에는 저장소를 가리키는 말만 둔다. 도구가 메모리에 쌓은 교정은 회고 입력이고 고른 것만 저장소로 옮긴다(POLICY §6). 회고 「멈춘 곳」은 스킬도 제안한다. 소비 레포가 옮길 일은 없다.
- 리뷰어는 PR 본문을 `gh api -X PATCH`로 쓴다. 그 실행 위치에서 쓸 수 없으면 Review 칸을 보고에 남기고, 로컬 세션이 `review-preflight`로 head를 다시 확인한 뒤 옮긴다(POLICY §3, `prompts/review.md` 8번). 소비 레포가 옮길 일은 없다.
- 리뷰어는 PR 본문의 Review 칸을 `python3 -I .baseline/baseline.py review-report <PR> --file <파일> [--thread <댓글 id>=<판정>]`로 쓴다. 형식이 틀리면 쓰지 않고, 판정한 스레드에 답하고 해결한 뒤 Review 절만 바꾼다. `enqueue`는 해결하지 않은 리뷰 스레드 수를 알리고, 해결된 스레드의 봇 답글은 늦은 리뷰로 세지 않는다.
- 이 저장소 `REVIEW.md`가 v1 경로(`templates/`·`profiles/`·`tools/`)를 v2 리뷰 기준으로 읽지 않게 했다. 소비 레포가 옮길 일은 없다.
- macOS에서 샌드박스를 켠 저장소는 settings의 `sandbox`에 `"enableWeakerNetworkIsolation": true`를 더한다. 그러면 `gh`와 `baseline.py`의 GitHub 명령이 샌드박스 안에서 돈다(WORKFLOW.md 「샌드박스 예시」).
- 샌드박스를 쓰는 로컬 세션은 엄격 모드(`allowUnsandboxedCommands: false`)를 끈다. macOS 샌드박스 안에서 `gh`가 TLS 검증에 실패해 `review-preflight`·`enqueue`·`budget`이 막힌다(WORKFLOW.md 「샌드박스 예시」).
- 스킬 사본은 `.claude/skills/`에만 둔다. 전역에 같은 이름의 스킬을 깔았으면 lock의 판에 맞춘다(WORKFLOW.md 「스킬 사본」). 소비 레포가 옮길 일은 없다.
- 실행 위치를 도구 이름이 아니라 종류(로컬, 원격 연결, 클라우드 단독, 클라우드 다중)로 본다. 모든 단계는 로컬 하나로 끝낼 수 있어야 하고, 스킬을 못 불러오는 도구는 `SKILL.md`를 직접 읽는다(WORKFLOW.md 「실행 위치마다 적용되는 것」). 소비 레포가 옮길 일은 없다.
- v2 저장소는 `python3 -I .baseline/baseline.py github plan`·`github apply`로 저장소 설정과 상태 라벨 5개를 맞춘다(소유자만). CI는 `github/ci.yml`을 복사하고 `patterns_allowed`에 `jdx/mise-action@*`를 더한다. ops를 켜면 `ops/ops.md`를 `docs/agents/ops.md`로 복사하고 `baseline.json`의 `profiles`에 `"ops"`를 더한다.
- v2 코어에 `.mise.toml`(빈 `[tools]`)이 생겼다. 판을 적으면 `run`이 `mise exec`로 돌고 `run setup`이 `mise install`을 먼저 한다. `github/ci.yml`을 다시 복사하면 ubuntu·macOS에서 돌고 `ci` job이 결과를 모은다(필수 체크 이름은 그대로 `ci`).
- `budget`은 공식 문서가 주는 파일별 상한만 검사한다: `AGENTS.md` 200줄, `REVIEW.md` 150,000바이트, `prompts/review.md` 500줄. 바이트 합계(리뷰어 읽기)는 출력만 한다. 근거는 #175 댓글에 있다. 소비 레포의 `AGENTS.md`·`REVIEW.md`는 고칠 것이 없다.
- `upgrade` 뒤 `check`가 `.gitignore`를 본다. `.env`·`.env.*`·`*.pem`·`*.key`·`*.p12`를 ignore하지 않으면 실패하니, 그 줄(`!.env.example` 포함)을 `.gitignore`에 더한다. 상태 라벨에 `wayfinder:*` 5개가 더해졌으니 소유자가 `github apply`를 한 번 다시 돌린다.
- 회고 프롬프트에 「리뷰 재현」 절을 더했다. 리뷰가 놓쳐 되돌린 PR을 다시 리뷰해 그 버그를 짚는지 본다. 「배운 규칙」 줄에는 적용 범위와 출처 PR을 붙인다. 이미 있는 규칙 줄은 고치지 않아도 된다.
- v2: `docs/agents/`의 `issue-tracker.md`·`domain.md`·`triage-labels.md`는 시작 파일이 됐다. 고쳐 써도 `check`가 실패하지 않고 `upgrade`가 덮어쓰지 않는다. `.gitattributes`는 맨 앞의 `* text=auto eol=lf` 줄만 관리하니, 그 아래에 저장소의 규칙(binary, LFS)을 더한다. `migrate`가 그 줄을 넣었으면 `git add --renormalize .`을 커밋한다.
  새 판의 코어 줄과 똑같은 저장소 줄이 코어 줄 바로 아래에 있으면, `upgrade`는 그 줄을 코어 줄로 본다. 판을 올린 뒤 `.gitattributes`의 diff를 확인한다.
- README·`docs/start.md`·`prompts/setup.md`를 v2(`init`·`migrate`·`upgrade`)로 다시 썼고 `VERSION`이 `2.0.0`이 됐다. v1 소비 레포는 `changelog.d` 항목을 옮기는 대신 `docs/start.md` 2절대로 `migrate`로 옮긴다.
  v1 `AGENTS.md`의 ops 블록(`<!-- repo-baseline:ops -->`)은 `migrate`가 옮기지 않으니 지우고 v2 `ops/README.md` 「켜기」로 다시 켠다.
- v2에 `migrate <경로>`가 생겼다. 기존 저장소를 v2로 옮기기 전에 이 명령으로 충돌과 계획을 보고, 막힘을 푼 뒤 `--apply`로 쓴다. 그다음 `.baseline/commands.json` 초안과 CI를 손으로 확인한다.
