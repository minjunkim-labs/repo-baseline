# v2.4.1

v2.4.0 뒤 쌓인 항목(첫째는 `changelog.d/`에서 모았고, 둘째는 이 릴리스 PR에 코드와 함께 들어와 노트에 바로 적었다)이다. 클라우드 enqueue를 처음 실제로 써 보며 드러난 보완 둘이라 patch를 올린다: workflow 파일 `github/enqueue.yml`(소비 레포가 손으로 다시 복사)과 `baseline.py`의 `enqueue-comment`(`upgrade`로 받는다). 판 올리기는 [docs/start.md](../start.md) 「판 올리기」대로 `python3 -I .baseline/baseline.py upgrade v2.4.1`이다. workflow 파일은 `upgrade`가 바꾸지 않으므로 아래처럼 손으로 다시 복사한다. 이 복사를 `upgrade` PR과 같은 PR에 넣으면 그 PR은 upgrade 예외를 잃고 어려움이 되므로, `upgrade` PR을 쉬움으로 두려면 따로 낸다.

- `github/enqueue.yml`: 댓글 작성자가 OWNER·MEMBER·COLLABORATOR(`author_association`)일 때만 job이 돈다(공개 저장소에서 아무나 `/enqueue` 댓글로 실행과 거절 댓글을 쌓지 못하게). `concurrency` group을 PR 번호에서 댓글 id로 바꿨다(같은 PR에 요청이 연달아 오면 대기 중이던 요청이 취소돼 답이 없던 것을 막는다). v2.4.0의 `.github/workflows/enqueue.yml`을 쓰는 소비 레포는 이 파일을 새 판으로 다시 복사한다. `.github/workflows/**`라 어려움 PR이고 소유자가 병합한다.
- 클라우드 세션의 `/enqueue` 댓글 끝에 도구가 붙이는 서명(`---`과 `_Generated by [이름](https://…)_` 한 줄, 이름은 40자까지이고 `<` `>`는 불가)을 받는다. 전에는 댓글이 `/enqueue <SHA>` 한 줄이 아니라는 이유로 workflow가 아무 답도 하지 않아 클라우드 `enqueue`가 100초 뒤 2로 끝났다(portfolio에서 처음 써 보다 확인). 이제 `/enqueue `로 시작하는데 읽을 수 없는 댓글(서명이 아닌 글, 짧은 SHA 등)에는 이유를 `refused`로 답한다. 서명 뒤에 다른 글이 있으면 여전히 거절하고, 요청 댓글에 그런 글이 붙으면 외부 리뷰로 센다. 소비 레포는 `upgrade`로 받는다. `baseline.py`가 바뀌어 어려움 PR이다. 주의: `issue_comment` 실행은 기본 브랜치의 옛 `.baseline/baseline.py`를 쓰므로, 소비 레포의 `upgrade v2.4.1` PR과 `enqueue.yml` 재복사 PR 자체는 클라우드 `enqueue`로 넣을 수 없다(서명이 붙은 요청이 다시 조용히 끝나고 100초 뒤 2로 끝난다). 이 둘은 어려움이기도 하니 소유자가 화면에서 넣는다.
